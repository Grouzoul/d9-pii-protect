d9 PII Protect.

L'anonymisation gouvernée des données personnelles pour vos agents IA.

FR-first · chiffrement réversible · déployé dans votre environnement

Le problème

Vos agents IA lisent vos données.
Y compris les données personnelles.

Le RBAC protège des champs entiers. Mais un NIR glissé dans un commentaire, un nom dans un ticket, passent en clair dans le contexte de l'agent — puis vers le modèle, les logs, la mémoire.

La solution

d9 gère qui accède.
PII Protect gère ce que l'agent voit.

Détection française + chiffrement réversible, appliqués à la source — avant que la donnée entre dans la chaîne de l'agent. Un humain autorisé ré-identifie sous contrôle.

Idée reçue

« Un LLM self-hosté ou Bedrock, ça suffit. »

01 · Droit

Minimisation (RGPD 5.1.c)

Une donnée personnelle non nécessaire à la tâche ne doit pas être traitée — où que tourne le modèle.

02 · Technique

La traînée

Ce que l'agent reçoit se recopie dans les traces, tool calls, mémoire, caches, logs, systèmes en aval.

L'hébergement décide le où. La protection du contenu décide le quoi.

La traînée de l'agent

1 appel modèle = 1 hop.
Un agent = N copies de la donnée.

Traces / observabilité❌ hébergement Tool calls❌ hébergement Mémoire / historique❌ hébergement Caches / logs❌ hébergement Systèmes en aval❌ hébergement

Tokeniser à la source couvre les N d'un seul coup : il ne reste qu'un endroit où la donnée est en clair.
